# dsh-lpipe-recall（回忆管线）

每轮组装请求时看一眼前面的话，把相关的旧记忆**模糊地**摆回模型面前。它不调模型、不写任何东西——星表与记忆都是只读的。

## 模糊回忆怎么选

1. 最近一条有效触发源是真文；主动调用时，`query` 就是真文。背景取真文之外最近 16K 字符的流水。
2. 真文和背景分别输入星图，得到真文闪烁星集合 A、背景闪烁星候选集合 B0；元素包含星信息、基础亮度和最后有效匹配位置。基础亮度已包含基础权重 × 长度系数 × 稀有度系数 × 最强匹配程度，与位置无关。先按星 ID 做差集 B = B0 − A，才得到背景闪烁星集合；随后回忆给真文乘固定系数、给背景乘位置系数，最后归一化背景预算。
3. 只有准确真文星能建立候选。通用星与准确星互斥；通用星、模糊星和准确背景星只给已有候选加分。
4. 排除冷却窗口内和当前可见回忆结果里的片段，将片段内不同闪烁星的亮度相加。对完整候选池施加时间、真文词面系数，再逐次选择掩盖后的前缀，默认最多取四段。
5. 每段默认选总亮度最高的两句原文，再按原文顺序排列，保留句子坐标，以省略号连接。

基础权重沿用准确星 1、模糊星 1、通用星 0.2；模糊星另乘数值或时间相似度。准确星长度系数为 `1 + min(1, max(0, L - 2) / 10)`，L 是归一化名称的 Unicode 字符数。稀有度系数为 `1 + log((N + 1) / (df + 1)) / log(N + 1)`，N 是片段总数，df 按不同片段计数，两种系数都不超过 2。真文来源系数为 3，背景原始来源系数为 `2 × 位置⁴`。

同一颗星若在真文点亮，取真文来源，不再占背景预算。令 F 为真文全部闪烁星亮度和、B 为剩余背景星的原始亮度和；背景各星统一乘 `F / B`，在本次窗口全局只算一次。背景最终总亮度等于 F，保留内部相对强弱；F 为零时不保留背景，B 为零时跳过除法。系数可以大于 1，不额外封顶。回忆只按星与片段的归属及亮度评分，不使用星线或星链权重。

准确星完整名称匹配程度为 1；连续局部匹配至少覆盖名称的 65%，且至少三个汉字或五个 ASCII 字符，匹配程度为 `0.5 × 覆盖率²`。数字、短名称和超过 64 字符的名称不做局部匹配。弱匹配不改变准确星类别。片段不再对模糊星或通用星另做总量封顶。


片段环境在星亮度求和 S 之后计算。设片段距今 a 天，近期记忆天数 D 默认 30：

- 时间系数 T = 1 + max(0, 1 − a/D)⁴；未来时间按 a=0，缺失时间不加成。此刻为 2，第 D 天及更早为 1。
- 真文与片段可读原文做 BM25，k1=1.2、b=0.75。分词使用汉字二元组和其他文字单词，全库片段提供 IDF 与平均长度；背景不参与查询。词面系数 L = 1 + b(M)/max候选 b；全部零分时 L=1。
- 未掩盖亮度 P = S × T × L。完整候选池都计算 T、L，不预截取。
- 已选前缀 E 对剩余候选的掩盖系数 H = 1 / (1 + Σ[N∈E] d(M,N))。d 是本次实际展示摘录的 IDF 加权词项 Jaccard；每个候选摘录先按既有选句规则冻结。
- 每轮选择 P×H 最大者加入前缀；同分比较准确真文星数量、时间，最后按片段键稳定裁决。所有前排共同掩盖后排，选满配置的 fragments 后立即停止，不计算后续名次。空摘录不占名额。

## 设置页

「Lpipe 设置」里的「回忆管线」块只放六项，窄屏自动换行；加载、校验、保存成功与失败都在块内反馈。数字可以写 `32K`、`1M` 或 `1.5M`，保存时只改这六项，`enabled` 等其他键原样留在文件里。保存后下一轮起生效。

| 键 | 默认 | 范围 | 含义 |
| --- | --- | --- | --- |
| `fragments` | `4` | 1–5 | 每轮最多摆几段 |
| `sentencesPerFragment` | `2` | 1–12 | 每段最多挑几句 |
| `inputChars` | `32000` | 2,000–32,000 | 本次触发源的最大字符数 |
| `backgroundChars` | `16000` | 8,000–96,000 | 真文之外的背景字符数 |
| `coolChars` | `1000000` | 32,000–4,000,000 | 回忆冷却窗口：模型还看得见的范围，不重复喂 |
| `recentDays` | `30` | 1–3,650 | 时间加成衰减到 1 的天数 |

配置文件仍是 `~/.dsh/life-recall/config.json`；面板不展示 `enabled`，要关总开关得直接改文件。

## 主动回忆

- `recall_fragments({ query })`：用自己的话描述要想起的事，返回相关旧片段的模糊摘录。沿用被动回忆的候选规则、近期原文冷却和可见结果去重。
- `recall_open({ repo, from, to?, count? })`：仓库 ID 单独填，起止坐标用 `片段ID:句子ID`，区间包含端点，可以跨片段。省略终点时默认读 20 句。

例如模糊回忆给出 `lpipe_recall_id[archive:219]`，其中第 13 句值得展开：

```js
recall_open({ repo: 'archive', from: '219:13', to: '220:3' })
```

一次最多返回 200 句、24000 字符，头部和提示也计入。连续原句只在本次首尾和跨片段分界两侧标完整句子 ID，中间不逐句编号。结果列出实际读到的片段及句数、仓库片段总数，并给出下一页坐标；达到上限会明确标为「已截断」。不存在的坐标和反向区间会报错。

工具返回的片段只在结果仍可见时参与已读排除；压缩或 rewind 隐藏结果后可以再次想起。只注册这两个工具，不提供片段目录和 `recall_find`。
