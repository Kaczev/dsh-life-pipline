# dsh-lpipe-recall（回忆管线）

每轮组装请求时看一眼前面的话，把相关的旧记忆**模糊地**摆回模型面前。它不调模型、不写任何东西——星表与记忆都是只读的。

## M1 做了什么

1. 取会话末尾 `matchChars`（默认 32K）个字符的原文；
2. 拿这段原文去点亮星表里的星星（准确星看名字，模糊星看「感觉」：20:46 想起 20:44、648 想起 648.5）；
3. 把闪烁星映射回它们出现过的那些轮，按「不同星求和」算片段强度；
4. 排掉落在 `coolChars`（默认 1M）之内的片段——那些模型本来就还看得见；
5. 取最强的 `fragments`（默认 2）段，每段挑最能点亮的那几句原句，用 `……` 连起来，作为一段上下文注入。

一颗星只留最强的一次点亮：同一个词说十遍，也不会让这段记忆显得十倍重要。

三种星的基础亮度：准确星 1、模糊星最多 0.3、通用星 0.2。模糊星是「感觉」，不是「说到了」，
所以它再像也只能给片段加一点点分量；候选还必须至少有一颗准确星撑着。

## 配置

`~/.dsh/life-recall/config.json`

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `enabled` | `true` | 总开关 |
| `fragments` | `2` | 每轮最多摆几段 |
| `matchChars` | `32000` | 回忆匹配窗口：多长的原文用来点亮星星 |
| `coolChars` | `1000000` | 回忆冷却窗口：模型还看得见的范围，不重复喂 |
| `minStars` | `2` | 一段记忆至少要有几颗闪烁星才准入 |
| `minStrength` | `1` | 强度门槛（位置权重 1.0–2.0） |
| `sentencesPerFragment` | `4` | 每段最多挑几句 |

## 已知的粗糙处（M1 故意留着）

- 数字型模糊星很松：`648` 能想起 `648.5`，也容易撞上别的数字。已经挡掉两位整数，但还没做「按量级分桶」的精确口径。
- 会话末尾 32K 若横跨很多话题，闪起来的星会非常多，片段排序偏长轮。这是按轮取值的副作用，之后要靠稀有度加权来压。
- 还没有主动工具（`recall_*`）——那是 M2 的「努力回忆」。
