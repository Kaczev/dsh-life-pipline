# 语气管线 · dsh-lpipe-tone

在「Lpipe 设置」的语气管线块中，分别填写措辞、句式、节奏和表达的显隐。四项只调整说话方式，不改变对用户的态度、回答内容或实际行为；不提供人物预设，也不自动学习。

## 四项设置

- `diction`（措辞）：决定用什么词表达同一个意思，例如日常还是书面、直白还是含蓄，以及称呼、语气词和比喻的使用习惯。不改变术语含义和事实。
- `syntax`（句式）：决定一句话怎么组织，例如长句还是短句、完整句还是口语省略，以及分句如何连接。不改变原有判断、条件和确定程度。
- `rhythm`（节奏）：决定话怎么展开、在哪里停顿，例如段落疏密、停顿、重复和重点的落点。不删减信息，也不为了节奏添加内容。
- `expression`（表达的显隐）：决定已有的情绪和语气表现得多明显，例如直接说出、通过语气词或括号动作表现，还是保持克制。不凭空增加情绪，也不改变对用户的态度。

初次使用提供简短英文默认值，目标是日常自然表达，用户可用任意语言修改。每项最多 32000 个 JavaScript 字符（UTF-16 code units），允许换行和制表符，不允许其他控制字符。正文原样保存，不裁掉前后空白。

空白项不生成对应章节，也不从其他项推导其风格。四项全为空白时，整个语气块返回空字符串，连共同边界也不注入。明确保存的空字符串不会被默认值填回。

有非空项时，宿主将英文共同边界和已填项依固定顺序合成提示词。语气适用于直接回复、进度说明、聊天工具中的用户可见正文，以及使用工具后的技术解释和结果汇报。事实、确定程度、否定、条件、权限、承诺及行动安排不因语气而变化；代码、命令、路径、ID、数值、引用和用户要求原样保留的文字不改写。工具执行字段不受语气影响。

语气配置是全局的。默认只对当前绑定的 LP 主会话生效；开启「所有顶层对话生效」后，未绑定为 LP 主会话的顶层对话也会收到语气提示词，子智能体仍不接收。关闭开关后恢复为仅 LP 主会话；改绑 LP 主会话不会清空配置。保存成功后，下次组装系统提示词时读取新值，不改历史，不新增模型调用、时间戳或正文插值。注入成功不代表输出已符合语气要求；请用实际对话验证效果。

## 设置页操作

「所有顶层对话生效」开关独立保存，不用点击下方的「保存」，也不会提交或丢弃文字草稿。开关保存失败时保留上次确认的状态，可再次切换重试。

四个多行输入框均显示中文解释与字符计数。每项标题右侧的「恢复默认」只将该项草稿填回宿主默认文字，不立即保存，也不影响其他项；与默认值相同或正在保存时不可用。空白表示不提要求，不等于默认值。

「保存」只在存在有效未保存改动时可用；「撤回」放弃草稿；「清空」将四项置空并立即保存。读取失败提供重试，不把错误显示成空配置。保存失败保留草稿，保存成功以宿主返回值更新基线，晚返回的响应不会覆盖后来输入的草稿。

## 配置与接口

配置位于 `DSH_HOME/life-tone/config.json`；未设置 `DSH_HOME` 时使用 `~/.dsh/life-tone/config.json`。保存使用临时文件及原子替换，保留磁盘未知键。损坏文件报错，不静默覆盖。

旧版空白的 `description` / `examples` 配置读取为新默认值。旧字段中有内容且没有新字段时，读取报错并保留原文件，不猜测它们属于哪个维度。先备份并整理旧文本，再明确提交全部四项进行迁移；旧字段仍留在磁盘，但不注入提示词。

使用宿主现有认证连接发送 `POST /api/dsh-lpipe-tone`，`Content-Type: application/json`：

```json
{
  "type": "client-request",
  "rpcId": "caller-generated-id",
  "method": "dsh-lpipe-tone",
  "payload": {
    "method": "tone.config.save",
    "payload": { "diction": "", "syntax": "", "rhythm": "", "expression": "" }
  }
}
```

`tone.config` 使用空 payload 读取四项文字、`allSessions` 和宿主默认值，成功返回 `{ ok: true, value: { config, defaults } }`。`tone.config.save` 接受至少一个已知字段的部分更新；例如 `{ "allSessions": true }` 只保存生效范围。`allSessions` 只接受布尔值，旧配置没有此字段时按 `false` 读取。文字字段以空字符串清空；未知字段、非法类型和超限均拒绝。保存成功返回 `{ ok: true, value: { config } }`。失败返回 `{ ok: false, error: { code, message, details } }`，封装于 `{ type: 'server-response', rpcId, result }`。
