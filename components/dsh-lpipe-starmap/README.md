# dsh-lpipe-starmap · 星图

把记忆层（`~/.dsh/life-memory`）里的原文拆成一颗颗**星星**：哪个概念在哪一轮说过，哪一句让它和另一颗星连在一起。

星图是索引层，不存正文、不写摘要、不做向量。原文永远只有一份，在记忆层；星图删掉能重建。

```
记忆层（原文，可校验）  →  星图（概念索引，可重建）  →  读取层（回忆 / 联想 / 想象）
```

## 灰与亮

- **灰色记忆**：记忆里已经存在、星图还没处理过的那部分。
- **亮色记忆**：已经构建完、被星图覆盖的那部分。
- 每轮 `turn/end` 之后自动接过来抽星；重启后补做所有灰记忆。

亮到哪里记在 `state.json` 的 `built` 里：

```json
{"version":1,"lex":3,"built":{"session-a4153e71…":{"turn":112,"to":3616}}}
```

`turn` 是已经处理完的最后一个轮号，`to` 是那一轮最后一条记忆行的 `seq`。先写星表、星源，最后才抬水位；崩在中间，重启重算那一轮，不会多出星。

## 磁盘

```
~/.dsh/life-starmap/
├── state.json                      { version, lex, built: { <sessionId>: { turn, to } } }
├── lexicon/<v>.json                词表快照：一版一个文件，只增不改
├── stars.jsonl                     星表：一颗星一行
└── sources/<sessionId>/<day>.jsonl 星源：一轮一行，句里是哪几颗星
```

星 id 是算出来的：`"s_" + sha256("zh|" + name).slice(0, 16)`。同样的名字永远同样的 id，重建不会多出第二颗同样的星。

不存星链：边是星源的视图，查询时现聚合（同句 1、相邻句 0.5）。全库 96 万条边物化要 185 MB，现算一次 0.04–0.8 ms。

## 星星从哪来

LLM 从用户正文、助手正文与思考、`chat_send` 发送正文提取概念对；普通工具输入和结果仅记忆，不抽星。程序过滤概念端点并确定落句和边权。

文字时间定位表达（刚刚、上周、过去三天等）用于匹配时间星，不得成为准确星或通用星；时间模板、时间范围、时区等机制概念仍可成星。数字和时刻继续按原规则生成模糊星，基础权重为 0.3。

本次保留规则版本 12，不触发整库重抽，旧索引不会自动清理。

## 查询

只读 RPC，端点 `/api/dsh-lpipe-starmap`：

| 方法 | 作用 |
|---|---|
| `starmap.progress` | 亮了多少轮、灰了多少轮、多少颗星、词表第几版 |
| `starmap.star` | 这颗星出现在哪些轮（`{ id }` 或 `{ name }`） |
| `starmap.turn` | 这一轮有哪几颗星（`{ key: "session#turn" }` 或 `{ session, turn }`） |
| `starmap.links` | 和谁相连、有多强、证据在哪句（`{ id, min, limit }`） |

## 星属性与匹配接口

读取层可导入 `dsh-lpipe-starmap/brightness` 的 `starProfile(repo)`，取得当前索引的通用星集合、稀有度和固有属性映射。固有属性合并基础值、名称长度与全库稀有度；新增记忆后基于新索引重算，不写入星表，不需要重新抽星。

`dsh-lpipe-starmap/match` 提供 `exactMatch` 和 `matchStars`。传入文本、星表及 `starProfile` 的结果，返回按星 ID 索引的闪烁星：星信息、基础亮度 `score`、最后有效匹配位置 `at`。基础亮度 = 固有属性 × 最强匹配程度，与位置无关；位置独立取最后有效命中。准确星位置采用归一化文本坐标，模糊星沿用原文坐标。星图不接收环境权重。回忆分别取得真文集合 A、背景候选集合 B0，按 ID 做差集得到背景集合 B，再施加环境权重和背景预算。
