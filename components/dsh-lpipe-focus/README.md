# 聚焦管线 · dsh-lpipe-focus

一段工作得出结果后，在开始下一段实质工作前调用 `focus_equate`。同一件事也可能经过几次简短问答才逐渐确定。如果下一次回复或行动要用到期间积累的决定、纠正或待答问题，先折叠再继续。其他时候可以直接回答或提问。折叠后，模型无法回看被替换的原文，提交前请对照整个区间检查遗漏。

## 一次调用，一个等效层

等其他工具返回后，模型单独调用 `focus_equate`。`key` 必须是本会话未用过的小写 kebab-case 标识；`supersedes` 也必填，只列新层仍完整保留其所需内容的旧层，没有就传 `[]`。

等效层的四个正文字段至少填一项。`definitions` 说明术语、流程及其适用范围。`experience` 保留可复用的做法和技能要求。`guidance` 记录仍会影响决定的偏好、约定和约束，写清来源、适用范围和约束强度。`conclusions` 保留已确定的事、待答问题和仍有疑问的判断。

`work_done` 记录做过或尝试过什么，以及实际观察到的结果。上述五个字段和独立的 `todos`、`next` 都按条填写。每条用 `content` 写一个要点，可用 `known` 和 `unknown` 分别补充该要点已知和仍待厘清的细节。三个值均为字符串，提供时须有实际文字。模型按分组标题阅读，组内各条按填写顺序显示。已知和待厘清的细节缩进在所属条目下。

`todos` 保存用户尚未完成的全部请求和问题。省略时继承现有待办，传入新列表时整体替换，传 `[]` 清空。`next` 只提示眼下该做什么，每次调用重新填写，用户最新指示优先。只要调用后的待办仍有条目，本次 `next` 就必须至少有一条。待办为空时，可省略 `next` 或传 `[]` 结束提示。

术语默认按最新定义理解。讨论过去的事时，可以按仍然可见的旧语境取义；如果旧义已不可见，不作推断。改一个词的含义不等于取代整个旧层。

第一次折叠跳过开头受保护的节点，以后紧接上一层，覆盖到本次调用的成功回执。聚焦保护系统提示词和工具定义。遇到系统消息，或者仍需依靠历史记录才能取得的工具定义，扫描就停。宿主能够独立提供完整工具定义时，结构化工具增删记录可以随区间折叠。应用注入的普通开发者消息和空占位都可折叠，模型用 `guidance` 保留仍然适用的约束及其来源。检查点之后的消息保持原序。

若要继续工作，仍需用到的原句、命令、标识、附件内容或技能要求，必须能从保留的上下文和工作区准确取得。保留来源，分清转述与核实的事实；第三方请求不等于用户授权。最近检查点的非空 `next` 单独出现在等效层之后，下次随新的工作区间替换；省略时不继承旧提示，也不从用户消息推断下一步。

DSH 从已保存的会话事件恢复上下文。`focus_equate` 的调用和回放都读取结构化条目列表。待办从来源中的 `entries` 恢复，每条的已知和未知细节都能保留。管线不删除聊天历史，也不保证提供方缓存命中。

`focus_equate` 与其他工具同时调用会返回参数错误，不替换上下文。宿主原生压缩进行中时，Focus 也不改写上下文。

本包只依赖生命核心。默认只对绑定的 LP 顶层会话及其子智能体启用聚焦。开启 `allSessions` 后，范围扩大到所有顶层会话。`includeSubagents` 默认开启，子智能体继承所属顶层会话的范围；关闭它只影响子智能体。它不依赖也不读写记忆、星图和回忆管线。

## 作用域与三项设置

在 **设置 → Lpipe 设置** 的聚焦管线块中，顶部的两个范围开关点击即存。下方可调整三项整数参数（字符数支持 `K`、`M` 简写，按约 2 字符折合 1 token 设定默认值）：

| 字段 | 标签 | 默认值 | 范围 | 作用 |
| --- | --- | --- | --- | --- |
| `idleMinutes` | 闲置整理时长 | `60` 分钟 | `5`–`1440` | 距最近一次模型交互达到该时长时，检查是否有已被显式覆盖的旧层可回收 |
| `compactChars` | 过线整理阈值 | `512K` 字符 | `32K`–`4M` | 表层加本步待入消息达到此值时，检查可回收层；仍有上下文压力时提醒模型检查旧层 |
| `nudgeChars` | 未转化提醒线 | `256K` 字符 | `16K`–`2M` | 从上次成功生成等效层起，跨轮累计模型输出和工具调用、结果的字符数，达到此值时提醒；须满足 `<= compactChars` |

同一对话中，上一轮读了 15 万字符，这一轮又读了 15 万，中间即使说过「继续」或加载过技能，只要还没生成等效层，就会越过默认的 25.6 万字符提醒线。用户消息、微信／QQ 聊天通知、宿主提示和受保护的技能调用及结果都不计数，也不中断累计。提醒过一次后，每新增半条提醒线的工作量（至少 8,000 字符）才再提醒。生成新层后重新累计；恢复同一会话不会重置计数。折叠时机取决于工作进展和下次回复所需的上下文，不必等提醒。

闲置或字符数过线只触发检查。在连续且通过校验的带键层中，程序只回收后层 `supersedes` 明确点名的旧层。若旧层还有需要的经验，而新层只更新了词义，就保留两层。没有可回收的层时不写替换事件。Focus 不限制等效层正文长度；模型仍受自身输出和上下文窗口上限约束。

上下文过线且已有带键层时，模型还可能收到检查旧层的提醒。提醒本身不会删除内容；宿主完成原生压缩也不单独触发回收。

「恢复默认」只把草稿填回默认值，保存后生效；「撤回」恢复已保存的值；「保存」仅在存在有效未保存改动时启用。

## 配置与接口

配置保存在 `DSH_HOME/life-focus/config.json`（未设置 `DSH_HOME` 时为 `~/.dsh/life-focus/config.json`），诊断日志写入同目录 `focus.jsonl`（2 MiB 自动截尾）。配置文件不存在时使用默认值且不提前建空目录；若文件 JSON 损坏或字段越界，读取直接报错并在设置页提供重试，不会用默认值覆盖原文件。保存采用同目录临时文件原子替换，并保留未知扩展键。

使用宿主认证连接发送 `POST /api/dsh-lpipe-focus`（`Content-Type: application/json`）：

```json
{
  "type": "client-request",
  "rpcId": "caller-generated-id",
  "method": "dsh-lpipe-focus",
  "payload": {
    "method": "focus.config.save",
    "payload": {
      "idleMinutes": 60,
      "compactChars": 512000,
      "nudgeChars": 256000
    }
  }
}
```

`focus.config` 接收空对象，返回 `{ ok: true, value: { config, defaults } }`；`focus.config.save` 接收至少一个已知配置字段并校验跨字段关系，返回 `{ ok: true, value: { config } }`。错误返回 `{ ok: false, error: { code, message, details } }`，外层封装为 `{ type: 'server-response', rpcId, result }`。

## 构建与测试

```bash
node components/dsh-lpipe-focus/scripts/build-client.mjs
node --test "components/dsh-lpipe-focus/test/*.test.mjs"
```

客户端面板由 `client/panel.js` 构建到 `lib/client.js`。等效层回归检查工作区间是否连续、后续消息是否原位保留、下一步提示能否独立写入或省略，以及旧层是否只在显式覆盖后回收。其余测试覆盖并发工具拦截、压缩锁、提醒频率、会话隔离、配置、RPC 和设置面板。
